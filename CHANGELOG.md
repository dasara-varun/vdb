# Changelog

## Unreleased — Audit hardening

The storage audit now acquires the per-instance lock before creating a new `VDB1` header, returns typed errors instead of panicking on recoverable collection, WAL, and serialization assumptions, and validates WAL length decoding without an unchecked conversion. WAL compaction writes and synchronizes a same-directory temporary file, atomically replaces the active path, reopens the append handle using version-preserving `SnapshotPut` records, and is covered by a regression test that verifies indexes, reopen, and subsequent writes. Replay now streams the WAL, validates semantic record references and version sequences, and supports format versions 1 and 2. JSON Lines imports and configured document limits are bounded, new database artifacts use private Unix modes, common symlink path hazards are rejected, and backup/export/manifest destinations refuse overwrites. New adversarial tests cover oversized imports, multiple-record JSON Lines import, invalid version sequences, legacy format reopening, output overwrite protection, Unix permissions, symlink rejection, larger configured documents, configuration limits, and quota rejection without partial appends. The core now exposes a configurable WAL quota with a 512 MiB default and 16 GiB maximum, and the CLI accepts `--max-wal-bytes`. Compaction rejects an oversized replacement before replacing the original WAL, with a regression test confirming the original database remains intact. The CLI now has contract tests for quota bounds and representative command parsing. JSON Lines import now reads one bounded newline-delimited record at a time; a regression test covers importing multiple exported documents, preventing the previous whole-file parse failure. A deterministic truncated-tail recovery regression verifies that a valid WAL prefix is retained and remains reopenable after repair. Nested equality filters now use the same dotted-path traversal for index lookup and final matching; regression coverage exercises both indexed and unindexed queries. Backup verification now requires an intact manifest and rejects symlinked backup or manifest paths. JSON Lines import now prevalidates a bounded batch and appends it as one synchronized WAL batch, so malformed input and quota failures do not leave partial logical state. Replay now fails closed on oversized WAL length prefixes and duplicate version-2 snapshot documents instead of treating them as repairable tails, with deterministic regression coverage. JSON Lines export now uses atomic create-new output semantics to close an overwrite race. The durability suite now truncates the final WAL record at every byte boundary and verifies valid-prefix repair. File synchronization at acknowledged WAL, compaction, backup, manifest, lock, and recovery-repair boundaries now attempts `sync_all`; directory-entry and power-loss guarantees remain platform-dependent and unproven. Unix lock acquisition now uses rustix’s safe nonblocking advisory exclusive lock, allowing stale regular lock files to be reused after process exit; a Unix stale-lock regression covers this behavior. Non-Unix targets retain the conservative create-new fallback until cross-platform locking evidence is available. A restore-to-new-path API and CLI command now require a valid backup manifest, preflight both destination files, refuse destination overwrites, reopen the restored database, and write a verifiable destination manifest; a regression proves an existing destination manifest is never modified and no database is created. CI now runs the workspace test suite natively on Ubuntu, macOS, and Windows; this is platform coverage, not power-loss certification. Directory-entry synchronization is now attempted after new database/header creation, secure backup/manifest creation, restore outputs, and Unix compaction replacement; non-Unix behavior remains unchanged and power-loss outcomes remain unproven. The repository now includes a Cargo.lock with registry checksums audited against the official sparse crates.io index, CI resolves it with `--locked`, and a pinned RustSec `audit-check` job is enabled; local Debian mirror source comparisons remain an environment limitation rather than a release claim. The Ubuntu release gate now runs a bounded Unix process-crash smoke harness that interrupts 64 CLI writes and reopens the database after each interruption; this is logical process-crash evidence, not power-loss or full compaction interruption certification. VDB now enforces a configurable maximum materialized document count during writes, imports, and replay, exposes it as `--max-documents`, and covers quota reuse after deletion plus lower-budget replay rejection; byte-level working-set bounds remain a separate roadmap item.

Documentation now records the exact header and compaction boundary, platform-dependent `rename` semantics, backup and stale-lock procedures, a cross-platform crash/fuzz testing strategy, dependency reproducibility constraints, and a ranked improvement plan covering encryption, advisory locks, memory-bounded storage, APIs, query planning, dependency auditing, and the constrained Steward roadmap. The repository also adds `AGENTS.md`, `CONTRIBUTING.md`, a central documentation index, a living project-status snapshot, documentation-maintenance rules, ADR guidance, reusable templates, and a pull-request checklist so future people and AI agents can keep project knowledge synchronized. Cross-platform installation and release-artifact guidance, an artifact workflow, a verified Claude Code tooling inventory, and bounded loop/session-handoff rules are now documented; third-party agent tooling remains optional and cannot override VDB safety policy. A root vulnerability-reporting policy and weekly Cargo/GitHub Actions Dependabot configuration provide explicit security-maintenance paths. The new durability matrix records the tested logical recovery boundary and cites official Rust filesystem and SQLite atomic-commit assumptions without treating them as universal power-loss guarantees. Developer-adoption research now documents the local-first product wedge, competing database lessons, a focused roadmap, and a measurable pilot plan.


## 0.2.0 — Rust MVP rebuild

This release replaces the exploratory Python prototype with a Rust workspace containing `vdb-core` and the `vdb` CLI. The core provides append-only CBOR WAL records with SHA-256 checksums, replay-based recovery, collections, nested JSON-like documents, optimistic versions, bounded equality queries, schema reports, health metrics, snapshot manifests, and backup verification.

The CLI supports initialization, collection creation/listing, document put/get/query/delete, schema inspection, equality-index creation/listing, health reporting, read-only Steward findings, backup creation/verification, JSON Lines export/import, and WAL compaction. The repository includes architecture, security, performance, data-format, operations, testing, demand-validation, production-gap, Steward, and roadmap documentation, plus GitHub Actions quality checks.

This remains an MVP. It does not yet provide encryption at rest, authentication, network serving, replication, or autonomous AI changes. The local core now includes a single-process lock, versioned/checksummed records, equality indexes, JSON Lines portability, and safe WAL compaction.
